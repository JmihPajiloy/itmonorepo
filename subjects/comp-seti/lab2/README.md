## Состав работы

- `captures/` — исходные pcap/pcapng захваты внешних измерений, управляемого учебного стенда и Телемоста.
- `stand/`, `compose.yaml`, `run_stand.py` — воспроизводимый стенд с двумя маршрутизаторами и службами HTTP, DNS, FTP и DHCP.
- `analyze.py`, `analyze_media.py`, `generated/` — извлечение проверяемых характеристик и построение таблиц/графиков из трасс.
- `run_external.py`, `collect_dns.py` — скрипты измерений выбранного узла ИСУ и отдельной полной DNS-записи.
- `report-core.typ`, `report-media.typ`, `references.bib` — редактируемые части отчёта и источники. Собственные схемы ICMP, HTTP и DNS построены по полям фактических пакетов.
- `screenshots/` — реальные скриншоты разбора сохранённых трасс в Wireshark 4.4.19.
- `DEFENSE.md` — вопросы и краткие ответы для подготовки к защите.
- `verification/` — журналы запуска, результаты проверок и аудит; `verification/attempts/` — сохранённые неудачные попытки, не используемые как результаты.
- [Сопоставление с заданием](verification/requirements.md) — все девять пунктов методички, подтверждающие трассы и адаптации условий опытов.
- `report.example.pdf` — исходный пример отчёта, сохранён без изменений.

## Воспроизведение

Для анализа сохранённых трасс нужны Python ≥ 3.9 и TShark 4.6.x; для PDF — Typst CLI, пакет `modern-g7-32` 0.2.0 и шрифты Times New Roman, Courier New. Docker Desktop нужен для нового запуска стенда. В папке работы:

```sh
make setup
make check
make report
```

Повторный запуск шести контейнерных опытов и проверка **именно нового** комплекта:

```sh
make experiments RUN=verification/runs/my-run
make check-stand RUN=verification/runs/my-run
make stop
```

`make experiments` создаёт новый каталог захватов; один и тот же путь повторно не используется. `make check-stand` читает захваты и скачанный FTP-файл из указанного `RUN`, сохраняет туда JSON, CSV, графики и журнал проверок. Он не требует новых браузерных опытов или звонков. Проверяющий скрипт также можно вызвать напрямую: `.venv/bin/python analyze.py --run-root verification/runs/my-run --stand-only`.

`make check` проверяет весь исходный комплект в `captures/` и обновляет `generated/`. Отсутствие обязательной трассы завершает проверку ошибкой. Новый запуск не меняет исходные трассы и числа отчёта. Из корня доступны `make check SUBJECT=comp-seti LAB=lab2` и `make report SUBJECT=comp-seti LAB=lab2`.

## Границы результатов

Фрагментация, HTTP 200/304, ARP, авторитативный DNS, FTP, DHCP и маршрут с двумя промежуточными маршрутизаторами исследованы на собственном стенде; они не выдаются за свойства серверов ИСУ. Обычный и условный GET также записаны в Chrome при загрузке учебной страницы стенда. В браузере подтверждён профиль ИСУ с ФИО, третьим курсом и группой N3352. Внешний HTTPS-запрос curl без авторизации получил 403; содержимое авторизованного профиля из сетевого дампа не расшифровывалось. Параметры сессии и номер студента не сохранены. DNS-запросы и внешние измерения описаны отдельно.

Для Телемоста сохранены самостоятельные аудио- и видеосеансы. В текстовом опыте две локальные вкладки одной учётной записи обменялись контрольными сообщениями через сервер; отправка и получение подтверждены интерфейсом обеих вкладок. Новая `captures/telemost-text.pcapng` содержит 59 пакетов выбранного TLS-соединения уведомлений ws.push.yandex.ru за 44,952695 с наблюдаемого интервала. Это часть сетевого обмена чата, поэтому её объём нельзя считать полным объёмом отправки сообщений. Прежняя пустая попытка перенесена в `verification/attempts/`.

Текстовые сообщения из TLS, звук и изображение из SRTP не расшифровывались. Анализируются время, размеры и открытые заголовки; привязка трафика к этапам сопоставляется с состоянием приложения.
