# Лабораторная работа №2 "Trial-version программа с системным сохранением лимитов"
Разработать простейшую программу, запрашивающую ФИО пользователя и заносящую эту информацию в текстовый файл. Если такое ФИО уже имеется в файле, то выдавать об этом сообщение. После ввода информации программа должна завершать работу и сообщать пользователю о лимитах ее использования (временнОго и количества запусков). По достижении лимита запусков программа должна предложить пользователю приобрести ее полную версию или деинсталлировать себя. При повторной установке программы, она должна сообщать о своем предыдущем нахождении на этом компьютере и сверяться с прошлыми лимитами пользования (т.е. не давать их суммарно превысить).

На защиту принимается инсталлятор, программа и деинсталлятор (программа регистрируется в системе, и Вы знаете, где это посмотреть и как ее «взломать»).
Выполняются две версии программы (можно сочетать в одной):
- а) Time-limited (ограничение по времени сделать не более 1-2 минут, чтобы можно было проследить в момент сдачи достижение лимита).
- б) Start-limited (ограничение на количество запусков тоже должно быть наглядным, например – 4-5).

На защите лабораторной – демонстрируется работа инсталлятора программы, который регистрирует её в системе и показывает начальные лимиты. Далее, запускаем несколько раз программу с возможным повтором имен, вносимых в базу. После достижения лимитов программа больше не запускается, даже после переинсталляции. Платформа любая.

Только после успешной защиты лабораторной работы формируется отчет и высылается преподавателю на почту

## Реализация и запуск

Платформа — macOS; зависимости — Python 3 из стандартной поставки. [install.py](install.py) копирует исполняемый `trial.py` в `~/.local/bin/itmo-timp-trial`, создаёт регистрацию `~/Library/Preferences/ru.itmo.timp.trial.plist` и папку данных `~/Library/Application Support/itmo-timp-trial`. [uninstall.py](uninstall.py) удаляет исполняемый файл, но сохраняет регистрацию и введённые ФИО. Переустановка обнаруживает прежнее состояние.

```sh
cd subjects/timp/lab2
python3 install.py
~/.local/bin/itmo-timp-trial
python3 uninstall.py
```

Программа запрашивает ФИО, записывает новое значение в `names.txt`, при повторе выводит сообщение и завершает работу. Лимиты совмещены: пять успешных запусков и 90 секунд от первой установки. После исчерпания любого лимита ввод не выполняется; показывается предложение приобрести полную версию либо запустить деинсталлятор. Счётчик увеличивается и при повторе ФИО. Установка выводит текущие остатки. Для просмотра регистрации можно открыть указанный `.plist` через `plutil -p`.

Для изолированной демонстрации можно задать `TIMP_TRIAL_HOME` как путь к отдельной папке и использовать эту переменную во всех трёх командах. Такая установка не затронет реальные пользовательские каталоги. Проверка: `make check SUBJECT=timp LAB=lab2`; она создаёт временную установку, проверяет повтор ФИО, лимит запусков и переустановку. Ветку окончания времени проверка вызывает изменением метки первой установки в тестовом `.plist`, без ожидания 90 секунд; затем удаляет временные данные.

Регистрация в пользовательском `.plist` и данные не защищены от владельца компьютера: изменение или удаление файла регистрации обходит лимит. Часы ОС тоже могут влиять на отсчёт; простое движение назад программа обнаруживает по `last_seen`, но это не защищённый источник времени. Это намеренно видимый для учебного анализа механизм. Инсталлятор не добавляет приложение в системный список пакетов macOS; под «регистрацией» здесь понимается запись в пользовательских Preferences.

Отчёт будет готовиться после успешной защиты, как требует задание.
