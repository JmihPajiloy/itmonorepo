# Отчёты Typst по ГОСТ

## Начало работы

Прочитать инструкции проекта, README выбранной работы и исходное задание целиком. Отделить обязательные требования от примеров и сопоставить их с разделами, данными и артефактами отчёта.

Для существующего отчёта сохранять его организацию и менять только относящиеся к задаче материалы. Реквизиты автора, группы и преподавателя брать только из задания, локальных инструкций или сообщения пользователя; неизвестные поля не заполнять заглушками.

## Оформление

- Использовать настоящий пакет Typst Gost с закреплённой версией, а не имитацию ГОСТ вручную заданными полями.
- Следовать титульному листу и правилам оформления, выбранным пользователем или проектом. Не переносить реквизиты из чужого образца.
- Не уменьшать шрифт, таблицы или листинги лишь для размещения на странице. Большой материал делить или переносить содержательно.
- Не использовать моноширинный `raw` в обычном тексте, включая имена файлов, таблиц, полей, SQL-ключевые слова и значения. В прозе оформлять их обычным шрифтом, при необходимости в кавычках. Моноширинное оформление оставлять только для самостоятельных листингов и примеров кода.
- Хранить редактируемый исходник диаграммы вместе с экспортом; подписи, ключи и обозначения должны быть читаемы при печати.

## Ссылки и источники

Включать в список использованных источников только материалы, на которых основаны содержание, теория, методика или исходное задание. Технические зависимости вёрстки источниками не являются. Если источник доступен публично, указывать URL и дату обращения.

Каждый источник из списка должен иметь хотя бы одну содержательную ссылку в основном тексте рядом с утверждением, которое он подтверждает. Для библиографии использовать `#bibliography("references.bib")` и ключи BibTeX в тексте, например `@source-key`. Не оставлять в списке источники, на которые текст не опирается.

Каждой нумерованной формуле, таблице и иллюстрации назначать устойчивую метку и явно ссылаться на неё через `@label`. Не вписывать номера вручную и не оставлять объект без смысловой ссылки в тексте.

## Сборка и проверка

Использовать команды сборки, заданные проектом. Перед изменением утверждений отчёта выполнять относящиеся к ним содержательные проверки. После изменения отчёта успешно пересобрать PDF; не сообщать об успешной проверке, если она не выполнялась.

Сохранять исходник отчёта, итоговый PDF и все материалы, необходимые для повторной сборки. В README указывать короткие команды установки и сборки, зависимости и существенные ограничения результата.
