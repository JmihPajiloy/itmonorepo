# Лабораторная работа № 1 по ПАСЗИ

Шибаев Иван Дмитриевич, группа N3352.
Тема: «Механизмы защиты Unix-систем».
Вариант 13: Parrot Security OS, автоматизированная система класса защищённости 1В.

## Результаты

- `report.pdf` — готовый отчёт в формате PDF.
- `report.typ` — исходник отчёта на Typst с пакетом `modern-g7-32` 0.2.0.
- `DEFENSE.md` — понятный конспект для защиты: что сделано, зачем нужны механизмы и какие ограничения есть у стенда.
- `task.md` — задание, перенесённое из сообщения пользователя.
- `references.bib` — нормативные и технические источники, на которые ссылается отчёт.
- `config/` — применённые настройки PAM, auditd, journald, OpenSSH, nftables и AIDE.
- `scripts/baseline.sh` — сбор исходного состояния виртуальной машины.
- `scripts/configure.sh` — идемпотентная настройка учебного стенда.
- `scripts/verify.sh` — функциональные проверки реализованных механизмов.
- `scripts/capture-terminal-output.sh` — сбор фактического терминального вывода для иллюстраций.
- `scripts/render-terminal-shots.py` — воспроизводимое оформление сохранённого вывода в виде окон Konsole.
- `verification/baseline.txt` — фактическое состояние Parrot OS до настройки.
- `verification/result.txt` — фактический результат проверки после настройки.
- `verification/terminal/` — неизменённый текст вывода команд, полученный с виртуальной машины по SSH.
- `screenshots/` — четыре терминальных снимка, включённых в отчёт.

## Стенд

Работа выполнена в UTM/QEMU на Parrot Security 7.3 (Echo), Debian 13.5, ARM64, ядро 7.0.7+parrot7-arm64. Сценарий установил и настроил auditd, AIDE, nftables и средства ACL, сохранив штатный AppArmor. SSH доступен только по ключу из локальной сети UTM.

## Проверка и сборка

Из корня репозитория:

```sh
make check SUBJECT=paszi LAB=lab1
make report SUBJECT=paszi LAB=lab1
```

Проверка не подключается к виртуальной машине повторно: она сопоставляет сохранённые фактические журналы с утверждениями отчёта. Для повторного эксперимента файлы `config/` и `scripts/` нужно скопировать на отдельный тестовый экземпляр Parrot OS, затем выполнить от root последовательно `baseline.sh`, `configure.sh` и `verify.sh`.

Терминальные иллюстрации созданы из сохранённого фактического вывода виртуальной машины, а не набраны вручную. При наличии Pillow их можно повторно сформировать командой `python3 subjects/paszi/lab1/scripts/render-terminal-shots.py` из корня репозитория.

## Существенное ограничение

Настройка демонстрирует сопоставление механизмов обычной GNU/Linux-системы требованиям руководящего документа 1992 года, но не аттестует Parrot OS как АС 1В. Полноценное соответствие не достигнуто: отсутствуют сертифицированные ФСТЭК средства защиты, принудительные метки конфиденциальности, организационный учёт носителей, автоматическая маркировка печати и физическая охрана. Это ограничение явно отражено в отчёте.
