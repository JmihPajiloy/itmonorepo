# Лабораторная работа № 2 по ИББД

Шибаев Иван Дмитриевич, Малышев Григорий Игоревич, N3352.
Тема: «Реализация БД в рамках СУБД».
Предметная область — мастерская реставрации музыкальных инструментов из [ЛР1](../lab1/README.md).

## Результаты

- `report.pdf` / `report.typ` — отчёт (Typst Gost `modern-g7-32` 0.2.0).
- `task.pdf` — исходное задание, `report.example.pdf` — пример отчёта из методички.
- `sql/01_tables.sql` — 9 таблиц; `02_relations.sql` — внешние ключи; `03_indexes.sql` — индексы;
  `04_alter.sql` — модификация структуры (`closed_on`); `05_data.sql` — данные (по 8 кортежей);
  `06_views.sql` — 4 представления из ЛР1.
- `check.sh` — пересоздаёт БД `workshop` и сохраняет выводы проверок в `verification/`.

## Зависимости

- PostgreSQL 14 (`initdb`, `pg_ctl`, `psql` в `PATH`; на macOS `brew install postgresql@14`).
- Typst CLI и пакет `@preview/modern-g7-32:0.2.0` для отчёта.

БД размещается в отдельном учебном кластере, который создаёт [`../tools/pg.sh`](../tools/pg.sh):
каталог `subjects/ibbd/.pgdata`, порт 55432, только 127.0.0.1. Порт и каталог меняются переменными
`IBBD_PGPORT` и `IBBD_PGDATA`. Остановить кластер: `../tools/pg.sh stop`.

## Команды

Из корня репозитория:

```sh
make check SUBJECT=ibbd LAB=lab2
make report SUBJECT=ibbd LAB=lab2
```

`check` удаляет и заново создаёт БД `workshop`, поэтому пользовательские изменения в ней теряются.

## Границы результата

Кластер учебный: суперпользователь `postgres` входит без пароля с 127.0.0.1. Правила переходов
статусов заказа, как и в ЛР1, не реализованы триггерами. Представления пока не ограничивают доступ:
роли и привилегии добавляются в ЛР3.
