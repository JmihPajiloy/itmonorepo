# Лабораторная работа № 4 по ИББД

Шибаев Иван Дмитриевич, Малышев Григорий Игоревич, N3352.
Тема: «Реализация сервиса для взаимодействия с разработанной базой данных».
Сервис — многопользовательский веб-интерфейс (Python, Flask, psycopg 3) к БД
`workshop` из [ЛР2](../lab2/README.md) с защитой из [ЛР3](../lab3/README.md).

## Результаты

- `report.pdf` / `report.typ` — отчёт, `task.pdf` — задание,
  `report.example.pdf` — пример отчёта из методических указаний.
- `webapp/` — приложение: `auth.py` (вход через СУБД, сеансы, CSRF, SCRAM-верификатор),
  `db.py` (доступные по привилегиям отношения и столбцы, выборка, вставка, изменение,
  удаление), `reports.py` и `sql/*.sql` (сводные запросы с GROUP BY по ролям),
  `__init__.py` (маршруты Flask), `templates/`, `static/`.
- `sql/01_admin.sql` — роль `admin_role`, учётная запись `workshop_admin`, политики RLS для
  администратора, функция регистрации `app_register_user` (SECURITY DEFINER).
- `check.sh` + `check.py` — пересборка БД и 49 автоматических проверок приложения на
  настоящей БД; фактические выводы — в `verification/` (`check.txt` и CSV для отчёта).
- `shots.py` — снимки экрана работающего приложения в Google Chrome (Playwright), `shots/`.

Вход выполняется учётной записью PostgreSQL: приложение открывает соединение от имени
пользователя, поэтому привилегии, столбцовые ограничения, RLS и журнал ЛР3 проверяет СУБД,
а в `change_log` попадает настоящая роль. Суперпользователь и вход без пароля
(trust для `postgres`) в веб-интерфейс не допускаются.

| Учётная запись | Роль | Отношений | Сводный отчёт |
| --- | --- | --- | --- |
| `reception_orlova` | приёмщик | 8 | оплаты по типам инструментов |
| `restorer_smirnov`, `restorer_volkova` | реставратор | 9 | работы по исполнителям и услугам |
| `workshop_admin` | администратор | 15 (все, включая журнал и шифртекст секретов) | выработка сотрудников; журнал по ролям |

## Зависимости

- Python 3 (проверено на 3.13.14), пакеты из `requirements.txt` в `.venv/`
  (Flask 3.1.3, psycopg 3.3.6; Playwright 1.63.0 — только для `make shots`).
- PostgreSQL 14 (`initdb`, `pg_ctl`, `psql`) — общий кластер [tools/pg.sh](../tools/pg.sh).
- Google Chrome — для снимков экрана; CLI Typst — для отчёта.

## Команды

```sh
make venv     # .venv и пакеты
make check    # пересобрать БД (ЛР2–ЛР4) и проверить приложение
make run      # http://127.0.0.1:5000
make shots    # снимки экрана в shots/
make report   # report.pdf
```

`make check` вызывает `../lab3/check.sh` с `IBBD_OUT` во временном каталоге (выводы ЛР3 не
перезаписываются), удаляет роли прошлого запуска ЛР4 (помечены комментарием `ibbd-lab4:`),
применяет `sql/01_admin.sql`, очищает журнал и запускает `check.py`. Проверка регистрирует
`reception_petrova` и `restorer_kozlov` (пароль `new-user-demo-pass`) и оставляет их в кластере
до следующего запуска. `make shots` выполнять после `make check`.

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `IBBD_RECEPTION_PASSWORD` | пароль `reception_orlova` | `reception-demo-pass` |
| `IBBD_RESTORER_PASSWORD` | пароль реставраторов ЛР3 | `restorer-demo-pass` |
| `IBBD_ADMIN_PASSWORD` | пароль `workshop_admin` | `admin-demo-pass` |
| `IBBD_PGHOST`, `IBBD_PGPORT`, `IBBD_DB` | подключение к СУБД | `127.0.0.1`, `55432`, `workshop` |
| `IBBD_SECRET_KEY` | ключ подписи cookie | случайный при каждом запуске |
| `IBBD_COOKIE_SECURE` | `1` — cookie только по HTTPS | выключено |
| `IBBD_WEB_PORT` | порт `make run` | `5000` |

## Границы результата

- Встроенный сервер Flask, HTTP, только 127.0.0.1; для эксплуатации нужны WSGI-сервер,
  HTTPS (`IBBD_COOKIE_SECURE=1`) и TLS до СУБД.
- Сеансы, соединения и счётчики неудачных входов хранятся в памяти одного процесса:
  теряются при перезапуске, не работают с несколькими процессами; на каждый сеанс —
  отдельное соединение с СУБД, пароль остаётся в памяти процесса, пока оно открыто.
- Блокировка после 5 неудач действует на пару «имя, адрес».
- Пароль при регистрации — только печатные ASCII (SASLprep не реализован).
- Администратор приложения — не суперпользователь, но может удалять строки основных
  таблиц; журнал и секреты ему доступны только для чтения (расширение правила ЛР3, где
  журнал читал только суперпользователь).
- Демонстрационные пароли по умолчанию не подходят для реального использования.
