# ЛР1: конспект для защиты

Этот файл объясняет работу с нуля: что было сделано, зачем это нужно и как показать результат преподавателю.

## О чём лабораторная

Тема работы — механизмы защиты Unix-систем. В качестве учебного стенда использована виртуальная машина с Parrot Security OS 7.3. По варианту она рассматривается как конечный узел в автоматизированной системе класса защищённости **1В**.

Смысл работы не в том, чтобы назвать Parrot OS «сертифицированной защищённой системой». Нужно было взять требования регулятора, найти доступные механизмы обычной Linux-системы, настроить их и доказать проверками, что они действительно работают.

## Короткая речь на защите

«Я выполнил настройку учебного стенда Parrot Security OS для демонстрации части требований к автоматизированной системе класса 1В. Сначала зафиксировал исходное состояние виртуальной машины и изучил требования руководящего документа. Затем настроил сложные пароли, разграничение доступа к защищаемым данным через группы и ACL, аудит событий, постоянное хранение журналов, SSH только по ключу, межсетевой экран nftables и контроль целостности AIDE. Для проверки я использовал отдельные технические учётные записи: читатель может читать файл, редактор — изменять его, а посторонний пользователь получает отказ. AIDE обнаруживает тестовое изменение файла, а две одинаковые резервные копии позволяют восстановить настройку. Все реализованные проверки прошли успешно. При этом я не утверждаю, что Parrot OS аттестована как АС 1В: для полного соответствия нужны сертифицированные средства защиты и организационные меры, которых в учебной виртуальной машине нет».

## Термины простыми словами

- **Unix/Linux-система** — операционная система, в которой есть пользователи, группы, файлы, процессы и права доступа.
- **Учётная запись** — имя пользователя, от имени которого выполняются действия.
- **Аутентификация** — проверка, действительно ли пользователь тот, за кого себя выдаёт. Например, по паролю или SSH-ключу.
- **Авторизация** — решение, что уже вошедшему пользователю разрешено делать.
- **PAM** — стандартный механизм Linux, который участвует в проверке паролей и входе в систему.
- **ACL** — расширенный список прав доступа к файлу или каталогу. Он позволяет выдать разные права нескольким группам, а не только владельцу и одной группе.
- **Аудит** — журналирование событий безопасности: кто и что сделал, к какому файлу обратился, какие настройки изменились.
- **Межсетевой экран (firewall)** — правила, которые решают, какие сетевые подключения разрешать, а какие запрещать.
- **Контроль целостности** — проверка, не изменились ли важные файлы с момента, когда их состояние считалось доверенным.
- **Контрольная сумма SHA-256** — короткий цифровой «отпечаток» файла. При изменении файла его отпечаток меняется.

## Что требовалось сделать

По варианту нужно было выбрать Parrot Security OS и систему класса 1В, определить применимые требования нормативной базы, настроить механизмы защиты Unix-системы и проверить результат.

За основу взят руководящий документ Гостехкомиссии России 1992 года о классификации автоматизированных систем и требованиях защиты от несанкционированного доступа. Для класса 1В особенно важны идентификация, разграничение доступа, регистрация событий, контроль целостности и организационные меры.

## Что именно сделано и зачем

| Механизм | Что настроено | Зачем это нужно |
| --- | --- | --- |
| Политика паролей | `pam_pwquality`: не менее 8 символов, нужны строчная и прописная буквы и цифра | Слабый пароль проще подобрать; политика уменьшает этот риск. |
| Разделение доступа | Группы `paszi_readers` и `paszi_editors`, права Unix и POSIX ACL | Читатель только читает, редактор может менять данные, посторонний не получает доступ. |
| Защищаемые данные | Каталог `/srv/paszi-lab1/protected` и файл `sample.txt` | Есть конкретный объект, на котором можно показать работу матрицы доступа. |
| Учебная метка | Расширенный атрибут `user.confidentiality=confidential` | Демонстрирует маркировку данных, но сам по себе не блокирует доступ. |
| Журналирование | `auditd` следит за учётными файлами, sudo, SSH, защищаемым каталогом, монтированием и привилегированными запусками | После инцидента можно понять, что происходило. |
| Постоянные журналы | `systemd-journald` хранит журнал на диске, включает сжатие и ограничение 256 МБ | События не должны исчезать после перезагрузки. |
| Удалённый доступ | OpenSSH: только ключи, root-вход и пароли выключены, максимум 3 попытки, X11 forwarding выключен | Уменьшается риск подбора пароля и удалённого входа под root. |
| Сетевая фильтрация | `nftables`: входящий и транзитный трафик запрещены по умолчанию; SSH разрешён лишь из сети UTM `192.168.64.0/24` | Узел не принимает лишние соединения из сети. |
| Контроль целостности | AIDE хранит контрольные суммы и свойства 47 важных объектов | Обнаруживает несанкционированное изменение конфигурации или защищаемых файлов. |
| Восстановление | Две совпадающие копии архива конфигурации и базы AIDE | Позволяет восстановить учебную настройку после повреждения. |
| Изоляция приложений | Штатный AppArmor оставлен включённым | Профили AppArmor могут ограничивать действия отдельных программ. |

## Как объяснить разграничение доступа

Для эксперимента созданы три технических пользователя.

| Пользователь | Роль | Результат проверки |
| --- | --- | --- |
| `paszi_reader` | Читатель | Может прочитать `sample.txt`, но не должен изменять его. |
| `paszi_writer` | Редактор | Может добавить строку в файл. |
| `paszi_denied` | Посторонний субъект | Не может даже прочитать файл: ядро возвращает отказ в доступе. |

Это и есть простая матрица доступа: для каждого субъекта определено, какие действия он может совершать с защищаемым объектом. Реализация опирается на владельца файла, группы, обычные права Unix и ACL.

У каталога установлен бит **setgid**: новые файлы внутри него автоматически получают группу редакторов. ACL по умолчанию задаёт права для создаваемых файлов, поэтому политика не теряется при добавлении нового файла.

## Почему журналирование и AIDE — разные вещи

`auditd` отвечает на вопрос: «какое событие произошло и кто его совершил?». Например, он фиксирует доступ к защищаемому каталогу.

AIDE отвечает на другой вопрос: «изменился ли важный файл по сравнению с доверенной базой?». Он сравнивает текущие SHA-256, владельца, права, ACL и расширенные атрибуты с ранее сохранёнными значениями. В проверке файл намеренно изменяется: AIDE должен сообщить о различии. Затем создаётся новая доверенная база, и повторная проверка снова чистая.

## Что показать преподавателю

1. Открыть [отчёт](report.pdf) и назвать стенд: Parrot Security 7.3, Debian 13.5, ARM64, виртуальная машина UTM/QEMU.
2. Показать матрицу доступа и объяснить роли трёх пользователей.
3. Открыть `verification/result.txt`: там есть результаты всех фактических проверок и строка `ALL IMPLEMENTED CHECKS PASSED`.
4. При демонстрации на стенде запустить от root `scripts/verify.sh`. Скрипт проверит службы, пароли, ACL, SSH, аудит, nftables, AppArmor, AIDE и резервные копии.
5. Показать, что AIDE обнаруживает контролируемое изменение, а затем после обновления базы расхождений нет.
6. Честно назвать ограничения: это учебный стенд, а не аттестованная АС 1В.

Для воспроизводимой проверки из корня репозитория используется команда:

```sh
make check SUBJECT=paszi LAB=lab1
```

Она проверяет сохранённые фактические журналы и соответствие утверждений отчёта. Она не подключается заново к виртуальной машине. Полный повтор эксперимента требует отдельной тестовой VM и запуска от root: сначала `baseline.sh`, затем `configure.sh`, затем `verify.sh`.

## Важные ограничения — это нужно сказать самому

Не нужно утверждать, что система полностью соответствует 1В. В работе реализована и проверена только доступная техническая часть требований. Полного соответствия нет, потому что:

- Parrot OS и установленные свободные пакеты не заявлены как сертифицированные ФСТЭК средства защиты от НСД;
- расширенный атрибут `confidential` — только учебная метка, он не реализует принудительное управление потоками по уровням конфиденциальности;
- нет автоматической маркировки печати, учёта носителей и гарантированной двукратной очистки освобождаемой памяти;
- виртуальная машина не моделирует физическую охрану и пропускной режим;
- AIDE запускается отдельно, а не как доверенный механизм контроля при загрузке;
- нет отдельного оперативного канала оповещения о попытках нарушения.

Такая формулировка — сильная часть защиты: она показывает, что вы отличаете практическую демонстрацию механизмов Linux от процедуры аттестации.

## Типовые вопросы и короткие ответы

**Почему выбран именно Parrot Security OS?**  Это дистрибутив из варианта. В работе использована Security Edition; она основана на Debian и содержит инструменты безопасности. Это не означает, что сама ОС сертифицирована для АС 1В.

**Что такое АС 1В?**  Это один из классов защищённости многопользовательских автоматизированных систем в выбранном руководящем документе. Для него требуются меры управления доступом, регистрации, целостности и организационной защиты.

**Почему парольный вход по SSH выключен, если пароли уже усложнены?**  Это разные уровни защиты. Сложные пароли полезны для локальной аутентификации, а SSH-ключи исключают удалённый подбор пароля по сети.

**Чем ACL лучше обычных прав `rwx`?**  Обычные права различают владельца, одну группу и остальных. ACL позволяет отдельно выдать права дополнительной группе читателей, не делая её основной группой файла.

**Зачем нужны и auditd, и journald?**  `journald` собирает системные сообщения служб. `auditd` ведёт специализированный аудит безопасности по заданным правилам. Их задачи пересекаются, но не совпадают.

**Зачем ограничивать SSH подсетью UTM?**  Даже при безопасной настройке SSH лучше уменьшить круг узлов, которые могут начать соединение. В стенде доступ разрешён только из локальной сети виртуализации.

**AIDE предотвращает изменение файлов?**  Нет. Он обнаруживает уже произошедшее изменение при проверке. Предотвращение выполняют права доступа, ACL, AppArmor и другие механизмы.

**Что доказывает совпадение двух резервных копий?**  Что на момент проверки созданы две одинаковые копии архива. Это помогает восстановить учебную конфигурацию, но не доказывает выполнение всех требований к резервированию для реальной АС 1В.
